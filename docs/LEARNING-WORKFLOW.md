# 操作学习流程

## 学习单位

学习单位不是“一个软件”，而是“一个软件中的一个业务动作”。Chrome 的“打开网址”和“下载文件”应分别学习；WPS 的“新建并保存”和“导出 PDF”也应分别学习。

## 需要录几遍

通常 2～3 遍足够形成第一版候选：

1. **基准示范**：最普通、最短的成功路径；
2. **变化示范**：改变窗口位置、大小、软件是否已运行或输入值；
3. **异常示范**：选择最常见的弹窗、已有文件、加载失败等分支。

次数不是标准。如果第一次就观察到稳定 UIA 标识或快捷键，第二遍的作用是证伪坐标依赖；如果三遍仍只能依靠图片像素，则应该先分析 UIA 树或换入口，而不是无限录屏。

## 从录制到 Profile

1. 给任务命名并分配 Action ID；
2. 声明输入、输出、副作用和成功证据；
3. 录制基准示范，标注每一步的业务意图；
4. 录制变化示范，区分常量与输入变量；
5. 比较 UIA、窗口、快捷键和视觉证据；
6. 生成 `draft` Profile；
7. 在专用测试数据上 dry-run，人工审阅计划；
8. 沙箱真实回放，通过后标记 `learned`；
9. 跨版本或跨语言回归后才标记 `validated`。

## 失败时记录什么

- 失败步骤 ID；
- 尝试过的定位器和降级路径；
- 前台进程、窗口标题、DPI、应用版本；
- 局部 UIA 树和遮蔽后的截图引用；
- 是否产生了文件或其他副作用；
- 可恢复建议。
