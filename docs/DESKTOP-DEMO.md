# 「照做」桌面演示器

「照做」是影核（ActionParity）面向旧软件的 Windows 兼容交互原型。产品口号是：

> 你做一遍，它照做；不是照着点，而是对结果负责。

## 为什么先做独立桌面程序

录制全局键鼠、读取前台窗口、保存可选截图和真实回放，都需要本机原生权限。PodApp
适合承载任务卡片、确认、远程触发和结果查看，但不应让 Pod/WebView 自己承担全局录制器。

第一阶段的边界是：

```text
照做桌面服务：录制 / 提炼 / 回放 / 验证
兼容动作档案：Action、输入、风险与证据契约
PodApp：以后接入的第二控制面与任务入口
```

## 启动

双击桌面的 `启动照做录制器.cmd`，或者在项目目录运行：

```powershell
pyw -3.11 -m desktop_app
```

## 演示流程

1. 描述这次任务的业务目标；
2. 可选填写成功标志（界面目前只填窗口标题；更强的证据种类可直接写进档案的 success_evidence）；
3. 点击“开始演示”，到目标软件完成一次操作；
4. 点击漂浮按钮或工作台中的“停止演示”；
5. 若动作还没演示完整，点击“继续补录”，追加下一段操作；新片段不会覆盖旧片段；
6. 检查自动生成的步骤和 `${text_N}` 输入变量；微信动作会优先显示
   `conversation` 与 `reply_text`；
7. 点击“检查计划”只做 dry-run，不操作键鼠；
8. 勾选授权后点击“真实执行”，3 秒倒计时内可取消，执行中可按 Esc 停止；
9. 执行器优先按 UIA 控件定位，再降级到窗口相对位置，最后才用绝对坐标；
10. 若最后一步被标为发送/发布/点赞，系统会先执行前置步骤并停在按钮前；
11. 用户检查目标、内容与账号后，再单独确认最终动作；
12. 执行后检查成功证据，并报告 UIA 命中与坐标兜底次数；
13. 应用重启后会恢复最近保存的动作；重新填写输入即可再次执行。

## 分段补录与重复执行

- 一个动作可以由多个 `segment_index` 片段组成，所有片段合并到同一条单调时间线；
- 典型微信动作可以分成“搜索并进入会话”“填写正文”“发送”“验证结果”四段；
- 追加片段后重新生成完整 Profile，最终副作用确认点会移动到新的最后一步；
- “重新演示”创建新会话，“继续补录”修改当前动作，两者语义不同；
- 重复执行不会保存上一次的输入正文，群名和回复内容需要重新提供；
- 当前只自动恢复最近动作，动作库、多版本和回滚仍是后续工作。

## 隐私与安全

- 可打印文字永远不写入录制文件，只记录长度并生成 `${text_N}`；
- 回放文字由用户在执行前重新提供；
- 截图默认关闭，开启时会明确提示可能包含敏感内容；
- Profile 默认是 `draft`，不能凭一次坐标录制宣称已经学会；
- 真实执行必须在界面中显式授权；
- 发送、发布、点赞等对外动作必须在最后一步发生当下再次确认；
- 鼠标与键盘动作可以用 Esc 中止。

## 当前验证结果

已在 Windows 实机完成：

```text
开始录制 → 在计算器点击数字 7 → 停止 → 生成 1 步 Profile
→ dry-run 通过 → 显式授权 → 真实回放 → 窗口证据通过
```

生成文件位于 `recordings/<session-id>/`：

- `events.jsonl`：原始遮蔽事件；
- `draft.action-profile.json`：候选兼容动作档案；
- `session.json`：会话摘要，包含 `segment_count`；
- `screenshots/`：仅在用户主动开启时产生。

## 还没有假装完成的部分

- 录制走 WH_KEYBOARD_LL / WH_MOUSE_LL 低级钩子，UIA 与窗口查询在钩子之外的工作线程做，
  钩子回调只入队（超时会被系统摘掉钩子）；
- 目前的“理解”是本地规则提炼，不是多模态模型推理；
- 回放已按可观察条件等待（窗口在不在、控件出来没有），没有锚点的步骤才回落到录制间隔，
  并在报告里单独计为“照秒表”步数；
- 已采集点击处和输入焦点的 UIA 控件身份，但尚未保存完整 UIA 树；
- UIA 失败时仍会退到窗口相对位置，需要更多跨版本回归；
- 成功证据已覆盖窗口、UIA 值与开关态、文件（存在/大小/内容变化）、剪贴板、进程；
  聊天软件的「消息真的出现在会话流里」「发布状态」仍未实现，会被明确判为未通过而不是默默放行；
- 一次演示只生成 `draft`，需要变化演示与回归后才能升为 `learned` / `validated`。
