# 社交与内容动作路线

目标动作不是“控制微信/抖音”，而是三个可验证、可审计的业务契约：

| Action ID | 目标 | 默认执行边界 | 成功证据 |
| --- | --- | --- | --- |
| `wechat.reply_message` | 回复指定微信会话 | 自动填草稿，发送前当下确认 | 指定会话出现回复内容摘要 |
| `wechat_official.publish_article` | 发布公众号文章 | 优先官方接口，发布前当下确认 | 后台出现 published 状态和标题 |
| `douyin.like_video` | 点赞用户指定的视频 | 定位视频，点赞前当下确认 | 点赞控件变为已选中 |

契约草案见 `profiles/social/action-contracts.shadow.json`。它们的状态是 `draft`，只是锁定
Action ID、输入、风险和证据，不表示已经适配某个微信或浏览器版本。

## 自动化原则

1. 有官方 API / SDK 时优先使用，GUI 只补最后一公里；
2. AI 可以选择目标、生成回复、填写内容和处理异常；
3. 发送、发布、评论、点赞、关注等代表用户对外行动，必须在动作发生当下确认；
4. 确认必须位于执行核心，不能只在 GUI 上藏一个按钮；
5. 不做批量养号、随机互动、验证码处理或绕过平台风控；
6. 自动回复先从白名单会话、固定时段、模板草稿和频率限制开始；
7. “点击完成”不算成功，必须检查消息、发布状态或控件状态。

## 建议实施顺序

1. 微信：打开指定会话 → 填入回复 → 停在发送前；
2. 公众号：文章草稿填充 → 封面/摘要检查 → 停在发布前；
3. 抖音：打开用户明确给定的视频 → 定位点赞控件 → 停在点赞前；
4. 收集每个动作 2～3 次变化演示，加入 UIA 与视觉回归；
5. 再把任务触发、手机确认和结果通知接进 PodApp。
