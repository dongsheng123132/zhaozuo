# Executor（执行器）

执行器读取已经审阅的兼容动作档案，解析动作输入，逐步定位控件、执行动作并收集成功证据。

当前版本只实现两件事：

- `validate`：校验档案的核心字段、步骤 ID 和输入占位符；
- `plan`：解析 `${input}` 并输出完整执行计划。

当前版本不会启动应用、点击、输入或写文件。真实 Windows 驱动接入后也应保持默认 dry-run，并要求调用方显式开启执行。

## 未来驱动层

1. `process`：发现/启动应用并绑定正确进程；
2. `uia`：使用 Windows UI Automation 查找、读取和调用控件；
3. `keyboard`：执行稳定快捷键和受控文本输入；
4. `vision`：只在 UIA 不可用时进行 OCR/视觉定位；
5. `evidence`：验证窗口、控件、页面状态或输出文件。

驱动失败时必须返回可区分的错误，不得静默退回未经声明的裸坐标点击。
